ForkliftAMR 인수인계 문서

1. 목적 / 역할

ForkliftAMR는 IsaacGym 시뮬레이션 안에서 포크리프트형 AMR(자율주행 이동로봇) 액터 하나를 제어하는 클래스다. 차동 구동(differential drive) 방식의 좌우 구동륜, 리프트 높이에 연동되는 조향 캐스터, 리프트를 제어하며, 목표 좌표까지의 직진 주행, 목표 각도로의 회전, 목표 높이로의 리프트라는 동작을 제공한다.

ForkliftMotionStep은 "어느 지점으로, 어떤 순서(X축 먼저/Y축 먼저)로, 어떤 방향을 보며, 얼마나 리프트를 올리고, 얼마나 정지 유지할지"를 선언적으로 기술하는 데이터 클래스다.

ForkliftStepRunner는 ForkliftMotionStep 리스트를 받아 내부 서브스테이지(0~6) 상태 머신으로 순차 실행하며, 매 서브스테이지마다 ForkliftAMR의 원자 동작을 호출해 "회전 → 1구간 이동 → 회전 → 2구간 이동 → 최종 회전 → 리프트 → 정지 유지"의 시퀀스를 수행한다 (로직(Runner)과 구동(AMR)의 분리).

StepContext는 wait_for/on_enter/on_complete 콜백에 전달할 임의의 context 객체를 키워드 인자만으로 간편하게 구성하기 위한 모듈 레벨 유틸리티 클래스다.

2. 클래스 다이어그램 + 호출 순서 시퀀스

2.1 클래스 관계

classDiagram class StepContext { +__init__(**extra) } class ForkliftMotionStep { -name -target_x, target_y -axis_order -initial_facing, direction1 -mid_facing, direction2 -final_facing -lift_height, lift_threshold -hold_seconds -wait_for -on_enter[], on_complete[] +__init__(name, target_x, target_y, axis_order, ...) } class ForkliftStepRunner { 주요 멤버 변수 -forklift: ForkliftAMR -steps: list~ForkliftMotionStep~ -context -index, sub_stage -_entered_current_step -_hold_start_frame -done +__init__(forklift, steps, context) %% 매 프레임 호출 메서드 +update(frame_count) %% 내부 전용 -_current_step() -_resolve_facing(explicit_facing, axis, target_coord, direction) -_advance_to_next_step(step) -_enter_hold(step, frame_count) } class ForkliftAMR { 주요 멤버 변수 -gym, sim, env, handle -TRACK_WIDTH, WHEEL_RADIUS -ARRIVE_THRESHOLD, ANGLE_ARRIVE_THRESHOLD -target_yaw_fixed -locked_turn_direction -dof_position_targets, dof_velocity_targets +__init__(gym, sim, env, handle) %% 초기 설정/튜닝 메서드 -_cache_joint_indices() +configure_actuators(damping, max_effort) +configure_contact_surface(caster_friction, drive_friction) -_configure_lift() %% 원자 동작(매 프레임 호출) 메서드 +get_pose() -_get_current_yaw(q) +set_twist_velocity(linear_x, angular_z) +turn_to_yaw(target_yaw) bool +drive_along_axis(axis, target_coordinate, direction) bool +set_lift_height(target_height) +get_lift_height() float +get_caster_angle() float +set_caster_angle(target_angle_rad) +hard_stop() +apply_actuator_commands() +seconds_to_frames(seconds) int %% 정적 유틸 +direction_to_yaw(direction_str) float +compute_axis_yaw(axis, axis_error, direction) float } ForkliftStepRunner --> ForkliftMotionStep : steps 리스트를 순차 실행 ForkliftStepRunner --> ForkliftAMR : forklift로 주입받아 동작 호출 ForkliftStepRunner --> StepContext : context로 주입받아 콜백에 전달(선택)

2.2 초기화 및 매 프레임 호출 순서

sequenceDiagram participant Caller as 호출부(env 생성 코드) participant AMR as ForkliftAMR participant Runner as ForkliftStepRunner Caller->>Caller: gym.create_actor(...) → handle Caller->>AMR: ForkliftAMR(gym, sim, env, handle) Caller->>Caller: steps = [ForkliftMotionStep(...), ...] 구성 Caller->>Runner: ForkliftStepRunner(forkliftamr, steps, context) loop Caller->>Runner: update(frame_count) Runner->>AMR: turn_to_yaw / drive_along_axis / set_lift_height / hard_stop 등 호출 Runner->>AMR: apply_actuator_commands() end

2.3 스텝 내부 서브스테이지 상태 머신 (sub_stage)

stateDiagram-v2 [*] --> SUB_INITIAL_FACING SUB_INITIAL_FACING --> SUB_SEGMENT1 : turn_to_yaw() 도달 SUB_SEGMENT1 --> SUB_MID_FACING : drive_along_axis(첫 축) 도달 SUB_MID_FACING --> SUB_SEGMENT2 : turn_to_yaw() 도달 SUB_SEGMENT2 --> SUB_FINAL_FACING : drive_along_axis(둘째 축) 도달 SUB_FINAL_FACING --> SUB_LIFT : turn_to_yaw() 도달 + hard_stop() SUB_LIFT --> SUB_HOLD : lift_height 도달(또는 lift_height=None이면 즉시) SUB_HOLD --> [*] : hold_seconds 경과 → 다음 스텝의 SUB_INITIAL_FACING으로 전환

wait_for가 지정된 스텝은 _entered_current_step이 False인 동안 wait_for(context)가 True를 반환할 때까지 SUB_INITIAL_FACING 진입이 보류된다(위 다이어그램의 [*] → SUB_INITIAL_FACING 이전 단계).

2.4 사용법 예시 (~/isaacgym/python/delivery_project/tests/test_forklift.py 기준) 

forklift_asset = load_asset(
    gym, sim, "urdf/forklift/forklift_v1.urdf",
    fix_base_link=False, replace_cylinder_with_capsule=True,
)
forklift_handle = gym.create_actor(
    env, forklift_asset, gymapi.Transform(p=gymapi.Vec3(-3.2, -2.125, 0.3)), "forklift_test", -1, 1
)
forklift = ForkliftAMR(gym, sim, env, forklift_handle)

gym.prepare_sim(sim)

steps = [
    ForkliftMotionStep(
        "INITIAL",
        target_x=-3.2, target_y=-2.125, axis_order='x',
        initial_facing='+x', direction1='FORWARD',
        mid_facing='+x', direction2='FORWARD',
        final_facing='+x',
        lift_height=-0.03, hold_seconds=0.1,
    ),
    ForkliftMotionStep(
        "MOVE_TO_SHELF_UNDER_AND_LIFT",
        target_x=-2.05, target_y=-2.125, axis_order='x',
        initial_facing='+x', direction1='FORWARD',
        mid_facing='+x', direction2='FORWARD',
        final_facing='+x',
        lift_height=0.16, hold_seconds=0.1,
    ),
    ForkliftMotionStep(
        "MOVE_SHELF",
        target_x=-2.5, target_y=-0.5, axis_order='x',
        initial_facing='+x', direction1='BACKWARD',
        mid_facing='+y', direction2='FORWARD',
        final_facing='-x',
        lift_height=-0.03, hold_seconds=0.1,
    ),
    ForkliftMotionStep(
        "MOVE_TO_SHELF_UNDER",
        target_x=-1.3, target_y=-1.0, axis_order='x',
        initial_facing='-x', direction1='BACKWARD',
        mid_facing='-y', direction2='FORWARD',
        final_facing='-y',
        lift_height=-0.03, hold_seconds=0.1,
    ),
]
runner = ForkliftStepRunner(forklift, steps, context=StepContext(forklift=forklift))

# 메인 루프에서 매 프레임:
if not runner.done:
    runner.update(frame_count)

3. Public API 레퍼런스

StepContext

메서드 역할 언제 호출해야 하는가
__init__(**extra) 전달받은 키워드 인자들을 setattr로 그대로 인스턴스 속성에 저장. 별도 필드 정의 없이 context.foo, context.bar처럼 임의 속성을 즉석에서 부여 가능 ForkliftStepRunner(forklift, steps, context=StepContext(robot=..., flag=False))처럼 wait_for/on_enter/on_complete 콜백에서 참조할 값들을 한 번에 묶어 넘기고 싶을 때

ForkliftMotionStep

메서드 역할 언제 호출해야 하는가
__init__(name, target_x, target_y, axis_order='x', initial_facing=None, direction1='FORWARD', mid_facing=None, direction2='FORWARD', final_facing='+x', lift_height=None, lift_threshold=0.002, hold_seconds=0.1, wait_for=None, on_enter=None, on_complete=None) 스텝 데이터를 필드에 그대로 저장하되, 다음 보정/검증을 함께 수행: ① axis_order를 strip().lower() 후 'x'/'y'가 아니면 ValueError 발생 ② hold_seconds를 max(0.0, hold_seconds)로 클리핑해 음수를 무시 ③ on_enter/on_complete가 None이면 빈 리스트로 대체(콜백 순회 시 None 참조 에러 방지) 시퀀스를 구성할 때 ForkliftMotionStep(...) 형태로 스텝마다 1회
필드 역할 비고
name 로그 출력용 스텝 식별자
target_x, target_y 도달할 목표 좌표
axis_order ('x' | 'y') 두 축 중 어느 축을 먼저 이동할지 'x'면 X축 먼저(1구간) → Y축(2구간), 'y'면 반대. 그 외 값은 __init__에서 ValueError
initial_facing, mid_facing 1구간/2구간 진입 전 정렬할 방향('+x'/'-x'/'+y'/'-y')
direction1, direction2 ('FORWARD'|'BACKWARD') 각 구간 주행 시 facing 기준 전진/후진 여부
final_facing 스텝 종료 시 최종적으로 바라볼 방향
lift_height 스텝 완료 조건에 포함할 목표 리프트 높이 None이면 리프트 단계를 건너뛰고 곧바로 hold로 진입
lift_threshold (기본 0.002m) 리프트 목표 도달 판정 허용오차
hold_seconds (기본 0.1) 리프트(또는 XY/방향) 도달 후 정지 유지 시간 __init__에서 음수는 0.0으로 클리핑됨
wait_for(context) -> bool 스텝 진입 자체를 지연시키는 선행 조건 None이면 즉시 진입
on_enter[], on_complete[] 스텝 진입/완료 시 호출되는 콜백 리스트 각 콜백은 context 인자를 받음. 생성자 호출 시 None이면 빈 리스트로 대체됨

ForkliftStepRunner

메서드 역할 언제 호출해야 하는가
__init__(forklift, steps, context=None) 스텝 리스트와 제어 대상(ForkliftAMR)을 주입받아 초기 상태(index=0, sub_stage=SUB_INITIAL_FACING) 구성. context는 wait_for/on_enter/on_complete 콜백에 그대로 전달되며, 필요하면 StepContext로 간편히 구성 가능 시퀀스를 실행하기 전 1회
update(frame_count=0) 현재 스텝의 서브스테이지를 진행시키고, 필요 시 ForkliftAMR의 동작을 호출한 뒤 apply_actuator_commands()로 마무리 매 시뮬레이션 프레임
_current_step() (내부 전용) self.steps[self.index], 즉 현재 진행 중인 ForkliftMotionStep을 반환 update() 내부에서만 호출됨. 외부에서 직접 호출할 필요 없음
_resolve_facing(explicit_facing, axis, target_coord, direction) (내부 전용) explicit_facing이 있으면 direction_to_yaw로 변환, 없으면 현재 위치와 목표 좌표의 오차 부호를 기반으로 forklift.compute_axis_yaw(...)를 호출해 자동으로 목표 yaw를 산출 SUB_INITIAL_FACING / SUB_MID_FACING 서브스테이지 진입 시 update() 내부에서 호출
_advance_to_next_step(step) (내부 전용) 현재 스텝의 on_complete 콜백들을 실행하고, index를 증가시키며 서브스테이지를 SUB_INITIAL_FACING으로 리셋. 마지막 스텝이면 done=True SUB_HOLD 완료 시 update() 내부에서 호출
_enter_hold(step, frame_count) (내부 전용) hold_seconds > 0이면 SUB_HOLD로 전환하고 시작 프레임을 기록, 0이면 곧바로 _advance_to_next_step 호출 SUB_LIFT 단계에서 리프트 도달(또는 lift_height=None) 시 update() 내부에서 호출
done (속성) 모든 스텝이 끝났는지 여부 시퀀스 종료 판정에 사용

ForkliftAMR

메서드 역할 언제 호출해야 하는가
__init__(gym, sim, env, handle) 조인트 인덱스 캐싱 + 액추에이터/접촉면/리프트 물리 파라미터 일괄 튜닝 액터 생성 직후 1회
_cache_joint_indices() (내부 전용) 좌/우 구동륜, 리프트, 좌/우 캐스터 조인트의 DOF 인덱스를 1회 조회해 캐싱하고, 못 찾으면 경고 로그 출력 생성자에서 1회 자동 호출
configure_actuators(damping=1000.0, max_effort=10000.0) 구동륜은 속도 제어(DOF_MODE_VEL) 모드로, 캐스터는 위치 제어(DOF_MODE_POS) 모드로 구동 특성(강성/감쇠/토크/속도 한계) 일괄 설정 생성자에서 1회 자동 호출(다른 파라미터로 재튜닝하고 싶을 때 직접 재호출 가능)
configure_contact_surface(caster_friction=0.0, drive_friction=2.5) 캐스터/구동륜/리프트 링크별로 마찰 계수 및 반발 탄성을 분리 설정 생성자에서 1회 자동 호출
_configure_lift() (내부 전용) 리프트 조인트를 위치 제어 모드로, 하중을 버틸 수 있는 강성/감쇠/속도/토크로 설정 생성자에서 1회 자동 호출
apply_actuator_commands() 누적된 포지션/벨로시티 버퍼를 Isaac Gym에 실제 주입 프레임당 마지막에 1회(Runner가 자동 호출)
get_caster_angle() 좌측 캐스터 조인트의 실제 현재 각도(rad)를 반환 캐스터 상태를 확인하고 싶을 때
set_caster_angle(target_angle_rad) 캐스터 각도를 리프트 연동과 무관하게 직접 지정(0.0~1.5708 rad로 클리핑) 리프트 연동 로직을 우회해야 하는 특수 상황
set_lift_height(target_height) 리프트 높이를 속도 제한으로 목표에 근접시키고, 높이-캐스터 각도 연동 테이블에 따라 캐스터 각도를 함께 갱신 리프트 변경이 필요한 매 프레임
get_lift_height() 현재 실제 리프트 조인트 위치(m) 반환 리프트 도달 판정 등에 사용
get_pose() 현재 전역 위치(p)와 회전 쿼터니언(r) 반환 필요 시
_get_current_yaw(q) (내부 전용) 쿼터니언 q로부터 yaw(rad)만 추출 get_pose()로 얻은 회전값을 다룰 때 내부적으로 호출
set_twist_velocity(linear_x, angular_z) ROS Twist 스타일의 선속도/각속도 명령을 받아 가속도(슬루 레이트) 제한을 적용한 뒤 좌/우 구동륜 각속도 목표로 변환해 버퍼에 기록 turn_to_yaw/drive_along_axis/hard_stop이 내부적으로 호출하는 최하위 구동 커맨드 함수. 커스텀 주행 로직을 직접 짤 때도 사용 가능
turn_to_yaw(target_yaw) 목표 yaw까지 회전 방향을 잠근 채(locked_turn_direction) 정밀 회전. 도달 시 True 방향 정렬이 필요한 서브스테이지에서 매 프레임
drive_along_axis(axis, target_coordinate, direction) 지정 축(X/Y)의 목표 좌표까지 직진하며 target_yaw_fixed로 자세를 유지. 도달 시 True 구간 이동 서브스테이지에서 매 프레임
hard_stop() 가속도 슬루 레이트 필터를 우회하고 이번 프레임에 즉시 속도 0 강제 서브스테이지 전환 등 "이 프레임에 확실히 멈춰야 하는" 지점
direction_to_yaw(direction_str) (static) '+x'/'-x'/'+y'/'-y' 문자열을 yaw(rad)로 변환 명시적 facing 처리 시
compute_axis_yaw(axis, axis_error, direction) (static) 축 오차 부호 + 진행방향으로부터 자동 정렬 yaw(rad) 계산 _resolve_facing()과 drive_along_axis()가 공통으로 사용하는 단일 소스
seconds_to_frames(seconds) LIFT_FRAME_DT 기준으로 초를 프레임 수로 환산 hold 시간 계산 등

5. 참고사항

  • ForkliftAMR의 본체가 바닥과 어느정도 떨어져 있으므로 무게를 변경하거나 속도를 변경할 때 흔들림이 발생할 수 있다. 이를 막기 위해 ForkliftAMR의 본체에 보이지 않는 캐스터 바퀴를 장착하는 등의 방법을 고려할 수 있다.
  • ForkliftAMR 지게의 무게 변경이나 화물의 무게가 많을 경우 lift_height가 목표값까지 도달하지 못할 수 있다. 이때 lift_threshold를 넉넉히 주거나, 리프트의 effort를 더 크게 설정하는 것을 고려할 수 있다.
