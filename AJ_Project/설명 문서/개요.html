1. 코드 간략 설명

IsaacGym 기반 창고 자동화 시뮬레이션이다. 하나의 env 안에 다음이 함께 배치된다.

  • Indy7 로봇팔 3대 (indy7_arm_1/2/3, IndyArmController) — 각각 컨베이어 픽업, 박스 접기, 패키지 적재를 담당
  • LowAMR 1대 — 저상형 리프트 AMR, 랙에서 화물을 들어 이동
  • ForkliftAMR 1대 — 포크리프트형 AMR, 팔레트를 다른 랙으로 이동
  • ConveyorBelt 1대 — 박스를 밀어 보내는 컨베이어
  • CardboardBoxManager로 관리되는 골판지 박스 8개 — 그중 1개(box_managers[0])만 실제 접기/적재 시나리오에 사용되고, 나머지 7개는 스폰만 되어 있음

전체 흐름(시나리오)은 "arm_2가 박스를 접음 → 컨베이어가 접힌 박스를 밀어보냄 → LowAMR이 랙 화물을 arm_3 앞으로 옮김 → arm_3가 화물을 박스 스테이션에 적재 → 컨베이어가 완성 박스를 최종 위치로 이동 → arm_1이 박스를 집어 팔레트에 올림 → 포크리프트가 팔레트를 랙으로 이동" 하나의 공정을 모사한다.

각 로봇의 자율 동작은 공통적으로 ~MotionStep(선언적 데이터) + ~StepRunner(서브스테이지 상태 머신) + context(콜백에 넘길 공유 상태 객체) 패턴으로 구현되어 있다 (ArmMotionStep/ArmStepRunner, LowAmrMotionStep/LowAmrStepRunner, ForkliftMotionStep/ForkliftStepRunner, ConveyorMotionStep/ConveyorStepRunner). CardboardBoxManager는 이 패턴에 속하지 않고, 대신 다른 러너들의 콜백(on_start/on_complete)에서 apply_stage() 등에서 호출되는 방식으로 엮인다.

3. 컨트롤러 간 실행 순서 / 동기화 (간단 도식)

5개 러너는 서로 직접 참조하지 않고, 딕셔너리 플래그(공유 상태) + wait_for 콜백으로만 느슨하게 연결되어 있다.

flowchart TD A["runner2 (arm_2, 박스 접기)"] -->|"runner2.done"| B["conveyor_runner: FIRST_MOVE (1.0m)"] C["low_amr_runner (랙→운반)"] -->|"MOVE_TO_DEST 완료 → _mark_low_amr_done() → low_amr_state.done=True"| D["runner3 (arm_3): MOVE_TO_PICK1 진입 허용"] D --> E["runner3: 패키지 2개 적재 진행"] E -->|"runner3.done"| F["conveyor_runner: SECOND_MOVE (2.0m)<br/>on_enter=_finalize_box_before_second_move<br/>(패키지 스캔·close_top·자식 오프셋 고정)"] B -.순차 실행.-> F F -->|"완료 → _mark_second_move_done() → conveyor_state.second_move_done=True"| G["runner1 (arm_1): MOVE_TO_PICK 진입 허용"] G --> H["runner1: 박스 픽업 → 컨베이어 등록해제 → 팔레트 부착"] H -->|"마지막 스텝 완료 → _mark_forklift_ready() → forklift_start_state.start=True"| I["forklift_runner: INITIAL 진입 허용 → 팔레트 랙 이동"]

사용되는 주요 공유 상태 3개 예시 (main 스크립트에서 dict로 정의됨):

플래그 누가 True로 만드나 누가 기다리나
low_amr_task_state["done"] low_amr_runner의 MOVE_TO_DEST 스텝 on_complete=[_mark_low_amr_done] runner3의 MOVE_TO_PICK1 스텝 wait_for
conveyor_task_state["second_move_done"] conveyor_runner의 SECOND_MOVE 스텝 on_complete=[_mark_second_move_done] runner1의 MOVE_TO_PICK(2번째) 스텝 wait_for
forklift_start_state["start"] runner1 마지막 스텝 on_complete=[..., _mark_forklift_ready] forklift_runner의 INITIAL 스텝 wait_for

5. 컨트롤러별 등록 및 사용법 예시

5.1 IndyArmController (로봇팔) 

arm = IndyArmController(gym, sim, env, viewer, arm_asset, spawn_transform=..., actor_name="indy7_arm_1")
# ... gym.prepare_sim(sim) ... 이후
arm.setup_tensors()
arm.register_attachable(box_handle)                 # 흡착 후보 등록
arm.register_joint_pose("init_pose", [...])          # 관절 프리셋 등록

def _attach(ctx): # 콜백 함수 등록
    ctx.arm.attach_nearest(distance_threshold=0.3) 

steps = [
    ArmMotionStep("MOVE_TO_INIT", "joint", target="init_pose"),
    ArmMotionStep("MOVE_TO_PICK", "cartesian_delta", delta_axis=2, delta_value=-0.12,
                   linear_speed=0.5, on_complete=[_attach]),
    ...
]
ctx = StepContext(arm=arm, box_managers=box_managers[0], ...)
runner = ArmStepRunner(arm, steps, context=ctx)

# 메인 루프에서 매 프레임:
arm.process_keyboard_input(events)   # 수동 조작용 키 바인딩 (선택된 팔만)
arm.step(); arm.update_attachment(); arm.draw_target_marker()
if not runner.done: runner.update(frame_count)
flush_dof_targets(gym, sim, arms)     # 팔 전체 목표각을 한 번에 물리엔진 반영
  • kind="joint"는 프리셋 이름, "cartesian_delta"는 현재 EE 기준 한 축 상대이동. on_complete에 _attach/_detach를 걸어 흡착 시점을 스텝에 맞춘다.
  • flush_dof_targets는 여러 팔 컨트롤러를 한 번에 반영하는 유틸 함수이며, arms 리스트(팔 3대)를 넘긴다.

5.2 LowAMR 

low_amr = LowAMR(gym, sim, env, low_handle)

def _mark_low_amr_done(ctx): # 콜백 함수 등록
    ctx.low_amr_state["done"] = True

steps = [
    LowAmrMotionStep(
        "MOVE_TO_CARGO",
        target_x=4.0, target_y=2.1,
        axis_order='y',
        initial_facing='+y', direction1='FORWARD',
        mid_facing='+x', direction2='FORWARD',
        final_facing='+x',
        lift_height=0.0,
        reset_lift_plate=True,
        lift_yaw_lock=False,
        hold_seconds=1.0,
    ),
    ...
    LowAmrMotionStep("MOVE_TO_DEST", ..., on_complete=[_mark_low_amr_done]),
]
low_amr_runner = LowAmrStepRunner(low_amr, steps, context=StepContext(low_amr_state=low_amr_task_state))
메인 루프: if not low_amr_runner.done: low_amr_runner.update(frame_count)
  • 리프트가 올라간 상태에서 회전해도 화물 방향이 안 틀어지도록 lift_yaw_lock=True를 스텝에 지정하면 Yaw-Lock이 걸린다.

5.3 ForkliftAMR 

forklift_amr = ForkliftAMR(gym, sim, env, forklift_handle)

forklift_start_state = {"start": False} # wair_for에서 참조할 딕셔너리 플래그 선언

steps = [
    ForkliftMotionStep(
        "INITIAL",
        target_x=-3.2, target_y=-2.125,
        axis_order='x',
        initial_facing='+x', direction1='FORWARD',
        mid_facing='+x', direction2='FORWARD',
        final_facing='+x',
        lift_height=-0.03,
        hold_seconds=0.1,
        wait_for=lambda ctx: ctx.forklift_start["start"],
    ),
    ...
]
forklift_runner = ForkliftStepRunner(forklift_amr, steps, context=StepContext(forklift_start=forklift_start_state))
메인 루프: if not forklift_runner.done: forklift_runner.update(frame_count)
  • LowAMR과 API 형태(MotionStep/StepRunner, axis_order, facing)가 거의 동일하나 클래스가 다르므로 서로 섞어 쓸 수 없다(예: ForkliftMotionStep을 LowAmrStepRunner에 넣으면 안 됨).
  • wait_for로 다른 러너의 진행을 기다리는 대표 예시.

5.4 ConveyorBelt 

conveyor = ConveyorBelt(gym, sim, env, conveyor_handle, belt_link_name="belt_link",
                         texture_frame_paths=frame_paths, speed=0.5)
conveyor.register_item(box_managers[0].handle)   # 벨트가 관리할 물체 등록
# ... gym.prepare_sim(sim) ... 이후
conveyor.setup_tensors(belt_length=3.5)

conveyor_steps = [
    ConveyorMotionStep("FIRST_MOVE", distance=1.0, direction='FORWARD',
                        wait_for=lambda ctx: ctx.runner2.done),
    ConveyorMotionStep("SECOND_MOVE", distance=2.0, direction='FORWARD',
                        wait_for=lambda ctx: ctx.runner3.done,
                        on_enter=[_finalize_box_before_second_move],
                        on_complete=[_mark_second_move_done]),
]
conveyor_runner = ConveyorStepRunner(conveyor, conveyor_steps,
                                      context=StepContext(conveyor=conveyor, runner2=runner2, runner3=runner3, ...))
메인 루프: if not conveyor_runner.done: conveyor_runner.update(frame_count)
  • 박스를 완전히 팔레트로 넘길 때는 unregister_item()으로 컨베이어 관리에서 빼야 자연 물리로 복귀한다(_release_from_conveyor 콜백).

5.5 CardboardBoxManager + BoxStageRegistry 

registry = BoxStageRegistry()
registry.register("unfolded_flat", {
    "joint_right_to_front": 10.0,
    "joint_right_to_back":  10.0,
    "joint_front_to_left": -10.0,
})
registry.register(
    "close_top",
    joint_targets_deg={
        "joint_right_to_up": 90.0, "joint_left_to_up": -90.0,
        "joint_front_to_up": 90.0, "joint_back_to_up": -90.0,
    },
    base="close_rl_bottom",
    lock_joints=["joint_right_to_up", "joint_left_to_up",
                 "joint_front_to_up", "joint_back_to_up"],
)
...

box_manager = CardboardBoxManager(gym, sim, env, box_handle, stage_registry=registry, joint_speed=1.2)
# ... gym.prepare_sim(sim) ... 이후
box_manager.setup_tensors()

# 스테이지 전환은 다른 러너의 콜백에서 호출됨 (예: ArmMotionStep.on_start=[_box_side_fold])
def _box_side_fold(ctx):
    ctx.box_managers.apply_stage("fold_sides")

box_manager.apply_stage("fold_sides")
box_manager.scan_and_capture(package_handlers, getter)   # 근처 패키지 자동 편입
box_manager.apply_stage("close_top")
box_manager.lock_children_offsets()                       # 이동 전 내용물 고정
box_manager.attach_to_platform(pallet_handle)              # 팔레트에 얹어 함께 이동

# 메인 루프: 매 프레임 전체 박스에 대해
for bm in box_managers:
    bm.update_joints(); bm.update_platform_lock(); bm.update_children()
