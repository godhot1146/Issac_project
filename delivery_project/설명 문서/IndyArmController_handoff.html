IndyArmController 인수인계 문서

1. 목적 / 역할

이 모듈은 IsaacGym 시뮬레이션 안에서 Indy7 로봇팔을 로딩·제어·시각화하기 위한 코드다.

  • IndyArmController: 로봇팔 액터 하나를 로딩·제어·시각화하는 클래스. end-effector를 좌표/회전으로 이동시키는 IK 모드, 관절각을 직접 적용하는 JOINT 모드, 관절 하나를 사용자가 직접 증감시키는 JOINT_MANUAL 모드를 하나의 클래스에서 전환하며 사용한다.
  • ArmMotionStep + ArmStepRunner: 이동 목표 · 속도 · 도달 후 대기시간(hold_seconds) · 시작/완료 콜백 등을 선언적으로 기술하는 ArmMotionStep들을, ArmStepRunner가 순서대로 재생한다.
  • flush_dof_targets(): 정해진 인터페이스(pending_dof_pos, dof_indices, actor_sim_index, dof_states_full)를 따르는 여러 로봇 컨트롤러의 목표 관절각을, 한 번의 set_dof_position_target_tensor_indexed 호출로 물리 엔진에 반영하는 유틸 함수.

2.3 ArmStepRunner 스텝 내부 진행 흐름

한 스텝은 "대기 → 시작 → 이동 → 안정화 → (선택)홀드 → 완료" 순서로 진행된다. 세부 조건은 §3.5(ArmMotionStep)·§3.6(ArmStepRunner)를 참고.

stateDiagram-v2 [*] --> WAITING_FOR_CONDITION WAITING_FOR_CONDITION --> STARTED : wait_for 통과 시 스텝 시작 STARTED --> MOVING MOVING --> STABILIZING : 모션 종료 STABILIZING --> HOLDING : 안정화 완료 (hold_seconds > 0) STABILIZING --> STEP_COMPLETE : 안정화 완료 (hold_seconds == 0) HOLDING --> STEP_COMPLETE : 대기 시간 종료 STEP_COMPLETE --> WAITING_FOR_CONDITION : 다음 스텝으로 STEP_COMPLETE --> [*] : 마지막 스텝이면 종료

2.4 사용법 예시 (~/isaacgym/python/delivery_project/tests/test_indyarm.py 기준) 

arm_asset = load_asset(gym, sim, "urdf/indy_description/urdf_files/indy7_v3_vacuum.urdf",
                        fix_base_link=True, density=100.0)
spawn_transform = gymapi.Transform(p=gymapi.Vec3(0.0, 0.0, 0.5))
arm = IndyArmController(gym, sim, env, viewer, arm_asset, spawn_transform=spawn_transform,
                         actor_name="indy7_arm_test")

dummy_asset = load_asset(gym, sim, "urdf/warehouse/dummy.urdf", fix_base_link=False, density=100.0)
dummy_handle = gym.create_actor(env, dummy_asset, gymapi.Transform(p=gymapi.Vec3(0.3, 0.0, 0.55)),
                                 "attach_test_dummy", -1, 0)

gym.prepare_sim(sim)
arm.setup_tensors()
arm.register_attachable(dummy_handle)
arm.register_joint_pose("init_pose", [-2.0255, 0.2495, 0.9428, -0.0014, 1.9548, 0.4432])

# 시퀀스 등록 및 러너 생성
ctx = StepContext(arm=arm)

def _attach(ctx):
    ctx.arm.attach_nearest(distance_threshold=0.3)

def _detach(ctx):
    ctx.arm.detach()

steps = [
    ArmMotionStep("MOVE_TO_INIT", "joint", target="init_pose"),
    ArmMotionStep("APPROACH_XY", "cartesian_delta", delta_axis=0, delta_value=0.2,
                  linear_speed=0.3, on_complete=[]),
    ArmMotionStep("APPROACH_Z", "cartesian_delta", delta_axis=2, delta_value=-0.1,
                  linear_speed=0.3, on_complete=[_attach]),
    ArmMotionStep("RETREAT_Z", "cartesian_delta", delta_axis=2, delta_value=0.1,
                  linear_speed=0.3, on_complete=[]),
    ArmMotionStep("BACK_TO_INIT", "joint", target="init_pose", on_complete=[_detach]),
]
runner = ArmStepRunner(arm, steps, context=ctx)

# 메인 루프에서 매 프레임
if not runner.done:
  runner.update(frame_count)
arm.process_keyboard_input(events)   # 수동 모드일 때만 — 자체 바인딩된 방향키/Z,X/T,Y,U,I,O,P 처리
arm.step()
arm.update_attachment()
arm.draw_target_marker() # 디버그 시 선택사항
arm.draw_ee_marker(color=(0.0, 1.0, 0.0)) # 디버그 시 선택사항
flush_dof_targets(gym, sim, [arm])

3. Public API 레퍼런스

3.1 모듈 레벨 함수

함수 역할 언제 호출해야 하는가
flush_dof_targets(gym, sim, controllers) pending_dof_pos가 있는 컨트롤러들의 목표를 모아 1회의 set_dof_position_target_tensor_indexed 호출로 반영 IndyArmController.step() 이후, 매 프레임 마지막에 1회(여러 로봇을 함께 다룰 때는 리스트로 한번에)

3.2 VelocityProfile

메서드 역할 언제 호출해야 하는가
__init__(keypoints=None, interp="smooth") (alpha, speed_fraction) 키포인트 리스트를 alpha 오름차순 정렬해 저장. 기본값은 [(0.0,0.1),(0.3,1.0),(0.7,1.0),(1.0,0.1)](사다리꼴형 가감속) LinearMotionGenerator 생성 시 커스텀 가감속 곡선이 필요할 때
speed_fraction(alpha) 진행률 alpha(0~1)에 대응하는 속도 배율(0~1)을 구간 보간(interp="linear"|"smooth")으로 반환 LinearMotionGenerator.step()이 매 프레임 호출

3.3 LinearMotionGenerator

메서드 역할 언제 호출해야 하는가
__init__(linear_speed=0.15, angular_speed=1.0, dt=1/60, velocity_profile=None) 직선 경로 궤적 생성기 초기화 IndyArmController.__init__()에서 1회 생성(self.motion_gen)
start(start_pos, start_quat, goal_pos, goal_quat) 시작/목표 포즈를 저장하고 총 이동거리·각도를 계산, active=True로 전환 move_to_cartesian()이 매 IK 목표 갱신 시 호출
_quat_angle(q1, q2) (내부 전용) 두 쿼터니언 사이 각도(rad)를 계산 start() 내부에서 총 회전각 산출용으로만 사용
slerp_quat(q1, q2, alpha) gymapi.Quat 두 개를 구면선형보간 step()이 내부적으로 호출. IndyArmController.update_attachment()도 LinearMotionGenerator.slerp_quat(...)으로 그대로 재사용
step() 속도 프로파일에 따른 배율 × linear_speed만큼 이번 프레임에 전진할 거리를 누적, 도달 시 active=False _compute_ik_mode()가 매 프레임 호출해 이번 프레임 웨이포인트를 얻음

3.4 JointMotionGenerator

메서드 역할 언제 호출해야 하는가
__init__(max_joint_vel, dt=1/60) 관절공간 궤적 생성기 초기화 setup_tensors()에서 device 확정 후 1회 생성(self.joint_motion_gen)
scurve_alpha(alpha) 5차 다항식(minimum-jerk) 기반 S자 진행률 변환(시작/끝 속도 0) quintic_interp() 내부에서 호출
quintic_interp(q_start, q_target, alpha) scurve_alpha로 변환한 진행률로 관절각을 minimum-jerk 보간 step()(synchronized=True 경로)이 호출
start(start_q, target_q, synchronized=True, min_duration=0.3) synchronized=True면 가장 느린 관절 기준으로 duration을 통일해 동시 도착, False면 관절별 독립 duration(도착 시점도 서로 다름) move_to_joint_pose()가 호출
step() 경과 시간 기반 알파를 quintic(동기 모드) 또는 관절별 알파(비동기 모드)로 변환해 다음 웨이포인트 반환, 도달 시 active=False _compute_joint_mode()가 매 프레임 호출

3.5 ArmMotionStep

파라미터 역할 비고
name 로그 출력용 스텝 식별자
kind ("joint"|"cartesian_abs"|"cartesian_delta") 이 스텝이 관절자세 이동인지, 절대 데카르트 좌표 이동인지, 현재 위치에서 한 축만 상대 이동인지 _is_active()/_start()가 분기 처리
target kind에 따라 관절각 텐서(또는 프리셋 이름) 혹은 (pos, rot) 튜플 kind="cartesian_delta"면 target 대신 delta_axis/delta_value 사용
delta_axis, delta_value kind="cartesian_delta"일 때 이동시킬 축 인덱스(0/1/2 각각 x/y/z에 대응)와 이동량
linear_speed, angular_speed 이 스텝 동안만 적용할 motion_gen의 속도(생략 시 기존 값 유지) _start()가 진입 시 arm.motion_gen에 덮어쓰고, 스텝 완료 시 _complete_step()이 자동으로 이전 값으로 복원한다
on_start, on_complete 단일 콜백 또는 콜백 리스트, __init__이 항상 리스트로 정규화 각 콜백은 StepContext 인자를 받음(예: attach/detach 트리거)
stable_frames (기본 10), stable_threshold (기본 0.0005) 모션 종료 후 EE가 이 프레임 수 연속으로 이 임계값 이내로 멈춰야 안정화 완료로 판정 ArmStepRunner._check_ee_stable()이 판정에 사용
hold_seconds (기본 0.0) 안정화 완료 후 다음 스텝으로 넘어가기 전 추가로 정지 유지할 시간(초). __init__에서 max(0.0, hold_seconds)로 음수 클리핑 0.0이면 기존과 동일하게 안정화 즉시 완료 처리. 0보다 크면 ArmStepRunner가 HOLDING 상태로 전환해 IndyArmController.seconds_to_frames(hold_seconds) 프레임만큼 대기
wait_for(ctx) -> bool 스텝 진입 자체를 지연시키는 선행 조건 None이면 즉시 진입

3.6 ArmStepRunner

메서드 역할 언제 호출해야 하는가
__init__(arm, steps, context=None) 스텝 리스트를 주입받아 초기 상태(idx=0, entered=False, _holding=False) 구성. arm.motion_gen의 현재 속도를 _prev_linear_speed/_prev_angular_speed로 저장한 뒤 즉시 arm.set_automation_active(True) 호출(안정화 판정은 별도 주입 없이 내부 _check_ee_stable()이 수행) 시퀀스를 실행하기 전 1회
_check_ee_stable(arm, prev_pos, threshold=0.0005) (내부 전용) 현재 ee 위치를 텐서에서 다시 읽어와 prev_pos와 비교, (현재위치, 변화량이 threshold 미만인지 bool) 반환 update()가 매 프레임 호출
_is_active(step) (내부 전용) step.kind=="joint"면 arm.joint_motion_gen.active, 아니면 arm.motion_gen.active를 반환 update() 내부에서만 호출
_start(step) (내부 전용) on_start 콜백 실행 → 오버라이드 전 속도를 저장 → 필요 시 step.linear_speed/angular_speed로 오버라이드 → kind에 따라 move_to_joint_pose/move_to_cartesian 호출 새 스텝 진입 시 update() 내부에서 1회 호출
_complete_step(step) (내부 전용) on_complete 콜백 실행 → motion_gen의 속도를 스텝 진입 전 값으로 자동 복원 → idx 증가, 마지막 스텝이면 done=True + arm.set_automation_active(False) 안정화 완료 직후(hold_seconds==0) 또는 HOLDING 종료 시 update() 내부에서 호출
update(frame_count=0) 현재 스텝을 진행시키고, 전체 시퀀스가 끝나면 True 반환. 안정화 완료 후 hold_seconds > 0이면 HOLDING 상태로 전환해 frame_count 기준으로 대기 시간을 판정한 뒤 _complete_step() 호출 매 시뮬레이션 프레임.

3.7 IndyArmController

초기화 / 설정

메서드 역할 언제 호출해야 하는가
__init__(gym, sim, env, viewer, asset, spawn_transform, actor_name="indy7_asset", stiffness=50000.0, damping_gain=1000.0, ik_damping=0.1, move_speed=0.01, rot_speed=0.05, linear_speed=5.0, angular_speed=1.0, max_joint_vel=None, lock_weight=3000.0, free_weight=1.0, dt=1/60) 이미 로드된 asset으로 actor 생성 → DOF 구동모드(DOF_MODE_POS)·강성·댐핑·effort 일괄 설정 → ee_name 확보 → 키보드 이벤트 바인딩까지 수행. 텐서 관련 필드는 None으로만 초기화(§ setup_tensors 참고) 액터 생성 직후 1회
_bind_keyboard_events() (내부 전용) 방향키(이동)/Z·X(Z축)/T·Y·U·I·O·P(회전 6종) 키를 뷰어 이벤트로 구독 생성자에서 1회 자동 호출
setup_tensors() gym.prepare_sim(sim) 이후 자코비안/rigid body/DOF state 텐서를 확보하고, ee/base 인덱스, joint_motion_gen, target_pos/target_rot, manual_joint_targets, actor_sim_index, root_states를 초기화 prepare_sim() 직후 반드시 1회
register_attachable(actor_handle) attach_nearest()의 후보 목록에 액터 핸들 추가(중복 방지) 흡착 가능한 물체를 씬에 배치한 직후
register_joint_pose(name, angles_rad) 이름-관절각 프리셋을 딕셔너리에 등록 반복 사용할 자세를 미리 정의할 때
seconds_to_frames(seconds) self.dt 기준으로 초를 프레임 수로 환산(round, 최소 0) ArmStepRunner가 hold_seconds 대기 판정에 사용.

자동화 락

메서드 역할 언제 호출해야 하는가
set_automation_active(active) automation_active 플래그를 갱신. True→False로 바뀌는 시점에는 manual_control_mode에 맞춰 control_mode를 다시 동기화(JOINT_MANUAL이면 enter_joint_manual_mode(), 아니면 현재 EE 포즈로 target_pos/target_rot을 갱신하고 IK로 복귀) ArmStepRunner가 자동으로 호출. 직접 호출은 커스텀 자동화 로직을 새로 만들 때만

모드 전환 / 관절 선택

메서드 역할 언제 호출해야 하는가
toggle_manual_control_mode() manual_control_mode를 IK ↔ JOINT_MANUAL로 전환. automation_active=True면 아무 동작도 하지 않고 경고 로그만 출력 키보드 "모드 전환" 액션(toggle_manual_mode) 수신 시
select_prev_joint() / select_next_joint() selected_joint_idx를 순환 이동(modulo) JOINT_MANUAL 모드에서 조작 대상 관절을 바꿀 때
enter_joint_manual_mode() 현재 실제 관절각을 그대로 목표(manual_joint_targets)로 삼아 control_mode/manual_control_mode를 JOINT_MANUAL로 전환 toggle_manual_control_mode(), set_automation_active(False) 복귀 시, adjust_selected_joint() 내부에서 호출
adjust_selected_joint(direction) direction(+1/-1) × manual_joint_step(기본 1도)만큼 선택된 관절의 목표각을 증감. automation_active=True면 조기 반환 JOINT_MANUAL 모드에서 관절 증감 키 입력 시

모션 명령(원자 동작)

메서드 역할 언제 호출해야 하는가
move_to_joint_pose(name_or_tensor, max_joint_vel=None, synchronized=True) 프리셋 이름 또는 텐서를 목표 관절각으로 삼아 joint_motion_gen.start() 호출, control_mode="JOINT"로 전환 관절자세 이동이 필요한 모든 지점(ArmStepRunner, 직접 호출 모두 가능)
move_to_cartesian(pos, quat) 현재 EE 포즈에서 pos/quat까지 motion_gen.start() 호출, control_mode="IK"로 전환 절대 좌표 이동이 필요한 지점(ArmStepRunner의 cartesian_abs/cartesian_delta, 키보드 IK 입력의 최종 단계 등)
compute_target_quat_from_relative_rpy(roll_deg, pitch_deg, yaw_deg) 베이스 링크 기준 상대 RPY(deg)를 월드 기준 목표 쿼터니언으로 변환 move_to_relative_orientation()이 내부적으로 호출
move_to_relative_orientation(roll_deg, pitch_deg, yaw_deg, keep_position=True) 위 함수로 목표 회전을 구하고, 회전축(3,4,5)을 1순위(lock)·위치축(0,1,2)을 2순위(free)로 설정한 뒤 move_to_cartesian() 호출 위치는 그대로 두고 자세만 정밀 정렬하고 싶을 때

입력 처리 / 매 프레임 계산

메서드 역할 언제 호출해야 하는가
process_keyboard_input(events) automation_active=True면 상태 리포트(start_process) 외 모든 입력을 무시하고 즉시 반환. 그 외에는 이동/회전/모드전환/관절선택·조작 액션을 분기 처리하고, 좌표/회전이 바뀌었으면 motion_gen.linear_speed를 MANUAL_LINEAR_SPEED(기본 5.0)로 고정한 뒤 motion_gen.start()로 재시작, 눌린 축을 active_axis_weights에 반영(우선순위 IK의 lock_mask 근거) 뷰어 키보드 이벤트를 폴링하는 매 프레임
step(max_joint_vel=None) 텐서 새로고침 후 control_mode에 따라 _compute_joint_mode/_compute_joint_manual_mode/_compute_ik_mode 중 하나를 실행해 pending_dof_pos를 채움(물리엔진 반영은 안 함) 매 프레임, flush_dof_targets() 호출 직전
_compute_joint_manual_mode() (내부 전용) manual_joint_targets를 그대로 pending_dof_pos에 복사 step() 내부에서만
_compute_joint_mode() (내부 전용) joint_motion_gen.step() 결과를 pending_dof_pos에 저장. None이면(이동 종료) pending_dof_pos도 None(이전 목표 유지) step() 내부에서만
_compute_ik_mode(max_joint_vel) (내부 전용) 현재 EE 오차(pos_err, rot_err)를 계산해 self.priority_ik()로 관절 변화량을 구하고, 필요 시 self.scale_to_joint_limits()로 속도 리밋 적용 후 pending_dof_pos 갱신 step() 내부에서만

IK 수학 유틸리티 (staticmethod, _compute_ik_mode() 전용)

메서드 역할 언제 호출해야 하는가
priority_ik(j_eef, dpose, lock_mask, damping_primary=0.05, damping_secondary=0.1) Siciliano 방식 태스크 우선순위 IK. lock_mask=True인 축을 1순위로 엄밀히 고정하고 나머지를 널스페이스에서 처리 _compute_ik_mode()가 매 프레임 self.ik_damping 기반 damping 값으로 호출(damping_primary=ik_damping*0.2, damping_secondary=ik_damping)
weighted_dls(j_eef, dpose, weights, damping) 축별 가중치 기반 Damped Least Squares IK(우선순위 IK의 대안) 현재 _compute_ik_mode()에서는 미사용. 축을 엄밀히 잠그지 않고 부드럽게 가중치만 주고 싶을 때 priority_ik() 대신 사용 가능
scale_to_joint_limits(d_theta, dt, max_joint_vel) 관절 간 이동 비율(방향)을 유지한 채 최대속도 초과분만 균일 축소 _compute_ik_mode(max_joint_vel)가 IK 결과에 속도 리밋을 적용할 때 호출

디버그 시각화 / 리포트

메서드 역할 언제 호출해야 하는가
draw_target_marker() 현재 IK 목표 위치(target_pos)에 파란 와이어프레임 구체 표시 뷰어 렌더 루프에서 디버깅 목적으로 매 프레임
draw_ee_marker(radius=0.04, color=(1,0,0)) 실제 EE 월드 위치에 구체 표시(기본 빨강) 위와 동일
quat_to_rpy_deg(qx, qy, qz, qw) (staticmethod) 쿼터니언(x,y,z,w)을 내재적 xyz 순서 Roll/Pitch/Yaw(deg)로 변환 print_status_report()가 내부에서 사용. 디버깅용 각도 확인 시 직접 호출 가능
print_status_report() EE의 월드/베이스-상대 좌표·회전(쿼터니언+RPY)과 전체 관절각(rad/deg)을 콘솔에 출력, 마지막에 관절각을 콤마로 구분된 raw 값으로도 한 번 더 출력(코드에 그대로 복사해 넣기 편하도록 하는 의도적 설계) 스페이스바 등 상태 확인용 키 입력 시(process_keyboard_input의 start_process 액션)

흡착(attach / detach)

메서드 역할 언제 호출해야 하는가
_distance_to_ee(target_sim_idx, ee_offset_world) (내부 전용) 대상 리지드바디와 EE(오프셋 반영) 사이 유클리드 거리 계산 attach(), attach_nearest() 내부에서
_get_root_indices(actor_handle) (내부 전용) 대상 액터의 SIM 도메인 액터 인덱스와 0번 리지드바디 인덱스를 반환 attach(), attach_nearest() 내부에서
attach(target_handle, distance_threshold=0.15, ee_local_offset=(0,0,0)) 거리 조건을 만족하면 EE 로컬 좌표계 기준 상대 위치/회전 오프셋을 계산해 저장하고 흡착 상태로 전환 그리퍼가 물체를 잡는 시점(주로 ArmMotionStep.on_complete 콜백)
attach_nearest(distance_threshold=0.15, ee_local_offset=(0,0,0)) attachable_handles 중 가장 가까운 물체를 찾아 attach() 호출 흡착 대상을 미리 특정하지 않고 자동으로 고르고 싶을 때
detach() 흡착 상태와 오프셋을 모두 초기화 물체를 내려놓는 시점
update_attachment(pos_gain=0.6, rot_gain=0.5) 저장된 오프셋 기준 목표 포즈를 계산해 pos_gain/rot_gain만큼 블렌딩(부분 텔레포트)하고 속도/각속도까지 함께 계산해 흡착 물체의 root state를 갱신(회전 보간은 LinearMotionGenerator.slerp_quat 재사용) is_attached=True인 동안 매 프레임

4. 튜닝 파라미터

파라미터 값 용도 / 근거
stiffness / damping_gain (DOF 전체) 50000.0 / 1000.0 IndyArmController.__init__에서 전체 DOF에 DOF_MODE_POS 강성/댐핑으로 일괄 적용. 위치 제어 모드에서 목표 관절각을 정밀 추종하도록 높은 강성 사용
effort (0~5번 관절) 각 10000.0 속도를 위해 실제보다 높은 값 사용
ik_damping 0.1 _compute_ik_mode()가 이 값을 그대로 사용해 priority_ik()를 호출한다: damping_secondary=ik_damping(자유 축), damping_primary=ik_damping*0.2(잠긴 축)
move_speed (기본 0.01) / rot_speed (기본 0.05) m/시간당-키입력, rad/시간당-키입력
MANUAL_LINEAR_SPEED (클래스 상수, 5.0) m/s 키보드로 수동 좌표 조작을 할 때 process_keyboard_input()이 매번 motion_gen.linear_speed에 강제로 설정하는 값
linear_speed (생성자 기본 5.0) / angular_speed (기본 1.0) m/s, rad/s LinearMotionGenerator의 초기 속도 상한. VelocityProfile이 정한 배율만큼만 이 값 이하로 낸다
max_joint_vel (기본) [2.61799, 2.61799, 2.61799, 3.14159, 3.14159, 3.14159] rad/s Indy7 각 축의 정격 최대 속도로 추정
dt (기본 1/60) 60Hz 시뮬레이션 가정 LinearMotionGenerator/JointMotionGenerator의 거리·시간 적분 기준이자 seconds_to_frames()의 환산 기준. 다른 스텝 주기로 시뮬레이션할 경우 반드시 함께 변경 필요
manual_joint_step np.radians(1.0) (약 0.01745 rad) JOINT_MANUAL 모드에서 키 1회 입력당 관절 증감량(1도)
stable_frames (ArmMotionStep, 기본 10) / stable_threshold (기본 0.0005m) 모션 종료 판정 후 "확실히 멈췄다"고 볼 프레임 수와 그 판정 임계값
hold_seconds (ArmMotionStep, 기본 0.0) 초 안정화 완료 후 추가로 정지 유지할 시간
distance_threshold (attach/attach_nearest, 기본 0.15m) 흡착 허용 최대 거리
pos_gain (기본 0.6) / rot_gain (기본 0.5) (update_attachment) 흡착 물체를 목표 포즈로 끌어당기는 블렌딩 비율. 1.0에 가까울수록 즉시 스냅, 낮을수록 관성감이 남지만 목표에서 뒤처짐
VelocityProfile 기본 키포인트 [(0.0,0.1),(0.3,1.0),(0.7,1.0),(1.0,0.1)], interp="smooth" 시작 10% 속도로 출발 → 30% 지점까지 가속 → 70%까지 최고속 유지 → 이후 10%로 감속. smoothstep 보간으로 가속도 급변 방지

5. 참고사항

  • process_keyboard_input 함수를 활성화 한 상태에서 스페이스바를 누르면 현재 로봇의 여러 상태들(좌표, 관절 각도 등)이 나오는데 이를 자주 확인하는 것을 권장한다.
  • 좌표(cartesian) 이동의 경우 로봇 팔이 해당 좌표로 이동하는 관절 각도 후보가 여러개 있으므로 로봇 팔의 끝부분은 같은 좌표에 있지만 자세가 달라질 수 있다. 이 경우 원하는 자세의 관절 각도를 확인하고 이동시키는 것을 권장한다.
  • 좌표(cartesian) 이동 중 로봇의 관절 회전이 최댓값이나 최솟값을 넘어가면 더 움직일 수 있을 것 같은데 못 움직이는 경우가 있다. 그러므로 현재 로봇이 얼만큼 회전했는지 확인하면서 좌표 이동을 권장한다.
