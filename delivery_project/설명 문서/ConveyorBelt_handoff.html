ConveyorBelt 인수인계 문서

1. 목적 / 역할

ConveyorBelt는 Isaac Gym 시뮬레이션 안에서 컨베이어 벨트 액터 하나를 제어하는 클래스다. Isaac Gym은 벨트 "메시" 자체를 물리적으로 이동시킬 수 없기 때문에, 이 클래스는 두 가지 트릭으로 컨베이어 동작을 흉내낸다:

(1) 벨트 위에 올라간 물체(박스 등)가 안착(landing)했다고 판단되면 매 프레임 로컬 +Y/-Y 방향 속도를 강제로 주입해 실제로 밀려가는 것처럼 만들고,

(2) 벨트 표면의 텍스처 프레임을 순차 스크롤해 시각적으로 벨트 자체가 움직이는 것처럼 보이게 한다.

2. 클래스 다이어그램 + 호출 순서 시퀀스

2.1 클래스 관계

classDiagram class ConveyorBelt { 주요 멤버 변수 -gym, sim, env, handle -belt_link_name, speed, dt -belt_rb_local_idx, belt_rb_sim_idx -texture_handles, num_frames -_texture_pixels_per_frame_base -is_texture_enabled -items: dict -running, direction, target_distance -_distance_ref_item, _moved_distance -root_states, rb_states, belt_length %% 초기화 메서드 +__init__(gym, sim, env, conveyor_handle, belt_link_name, texture_frame_paths, speed, dt) +setup_tensors(belt_length) %% 내부(private) 헬퍼 메서드 -_recompute_texture_scroll_rate() -_start_run(direction, distance) -_get_belt_pose() -_update_item(st, belt_p, belt_r) bool -_update_distance_tracking() -_push_root_states(updated_indices) -_scroll_texture() %% 매 프레임 호출 메서드 +update(frame_count) %% 이벤트/조건부 호출 메서드 +move_forward(distance) +move_backward(distance) +stop() +set_speed(new_speed) +register_item(actor_handle, root_link_index) bool +unregister_item(actor_handle) +set_item_grabbed(actor_handle, grabbed) +reset_item_landing(actor_handle) +seconds_to_frames(seconds) int +moved_distance : float } class ConveyorMotionStep { 주요 멤버 변수 -name, distance, direction -hold_seconds, wait_for -on_enter, on_complete +__init__(name, distance, direction, hold_seconds, wait_for, on_enter, on_complete) } class ConveyorStepRunner { 주요 멤버 변수 -conveyor: ConveyorBelt -steps: list~ConveyorMotionStep~ -context, index, sub_stage -_entered_current_step, _hold_start_frame -done +__init__(conveyor, steps, context) %% 매 프레임 호출 메서드 +update(frame_count) %% 내부(private) 헬퍼 메서드 -_current_step() -_advance_to_next_step(step) -_enter_hold(step, frame_count) } ConveyorStepRunner --> ConveyorBelt : 제어(move_forward/move_backward, running 조회) ConveyorStepRunner --> ConveyorMotionStep : 순차 실행

2.2 초기화 순서

sequenceDiagram participant Caller as 호출부(env 생성 코드) participant Belt as ConveyorBelt Caller->>Caller: gym.create_actor(...) → conveyor_handle Caller->>Belt: ConveyorBelt(gym, sim, env, conveyor_handle, belt_link_name, texture_frame_paths, speed) Caller->>Caller: (모든 env의 액터 생성이 끝난 뒤) gym.prepare_sim(sim) Caller->>Belt: setup_tensors(belt_length)

setup_tensors()를 호출하기 전에 update()를 호출하면 self.root_states가 None이라 RuntimeError가 발생한다.

생성자 호출 → prepare_sim → setup_tensors 순서를 지켜야 한다.

2.3 ConveyorStepRunner 서브스테이지 흐름 (스텝 1개당)

stateDiagram-v2 [*] --> SUB_MOVING: wait_for(context) 충족 시 on_enter 콜백 실행 후 move_forward/move_backward 호출 SUB_MOVING --> SUB_HOLD: conveyor.running == False 이고 hold_seconds > 0 SUB_MOVING --> [*]: conveyor.running == False 이고 hold_seconds == 0 (on_complete 실행 후 다음 스텝으로) SUB_HOLD --> [*]: hold_seconds 경과 (on_complete 실행 후 다음 스텝으로)

2.4 사용법 예시 (~/isaacgym/python/delivery_project/tests/test_conveyor.py 기준) 

conveyor_asset = load_asset(gym, sim, "urdf/conveyor/v2/conveyor_v2.urdf",
                             fix_base_link=True, density=1000.0)
conveyor_pos = gymapi.Vec3(0.0, 0.0, 0.05)
conveyor_rot = gymapi.Quat.from_axis_angle(gymapi.Vec3(0, 0, 1), np.radians(90.0))
conveyor_transform = gymapi.Transform(p=conveyor_pos, r=conveyor_rot)
conveyor_handle = gym.create_actor(env, conveyor_asset, conveyor_transform, "conveyor_test", -1, 0)

# 벨트에 태울 물체
box_asset = load_asset(gym, sim, "urdf/cardboard_box/v2/box_v2.urdf", fix_base_link=False, density=100.0)
box_start_pos = gymapi.Vec3(0.0, 0.15, 1.2)
box_handle = gym.create_actor(env, box_asset, gymapi.Transform(p=box_start_pos), "conveyor_test_box", -1, 0)

registry = build_registry()
box_manager = CardboardBoxManager(gym, sim, env, box_handle, stage_registry=registry, joint_speed=1.2)

frame_paths = sorted(glob.glob(os.path.join(ASSET_ROOT, "urdf/conveyor/v2/anim/*.png")))
conveyor = ConveyorBelt(
    gym, sim, env, conveyor_handle,
    belt_link_name="belt_link",
    texture_frame_paths=frame_paths,
    speed=0.5,
)

gym.prepare_sim(sim)

box_manager.setup_tensors()
box_manager.set_initial_spawn_stage("close_top")

conveyor.setup_tensors(belt_length=3.5)
conveyor.register_item(box_handle)

# 시퀀스 등록 및 러너 생성
steps = [
    ConveyorMotionStep("FWD", distance=1.0, direction="FORWARD", hold_seconds=1.0),
    ConveyorMotionStep("BWD", distance=1.0, direction="BACKWARD", hold_seconds=1.0),
]
runner = ConveyorStepRunner(conveyor, steps, context=StepContext(conveyor=conveyor))

# 메인 루프에서 매 프레임
if not runner.done:
    runner.update(frame_count)             # 시나리오 모드
# 또는
conveyor.update(frame_count)               # 수동 모드 (move_forward()/move_backward() 등 직접 호출 시)

# 벨트에 태울 물체도 메인 루프에서 매 프레임
box_manager.update_joints()
box_manager.update_platform_lock()
box_manager.update_children()

3. Public API 레퍼런스

모듈 레벨 헬퍼 함수

(클래스 외부에 정의된 일반 함수 2개. 별도의 "유틸리티" 클래스나 모듈로 묶여 있지 않다.)

함수 역할 호출하는 곳
_world_to_local(origin_pos, origin_rot, world_pos) 월드 좌표(world_pos)를 기준점(origin_pos, origin_rot) 기준 로컬 좌표로 변환(위치 차이를 구한 뒤 기준 회전의 역회전을 적용) ConveyorBelt._update_item()이 거리 추적용 local_pos(로컬 y 위치)를 계산할 때 사용
_flatten_keep_yaw(rot) 쿼터니언에서 roll/pitch만 0으로 눌러 수평으로 정렬하고, yaw(z축 회전)는 그대로 유지한 새 쿼터니언 반환 ConveyorBelt._update_item()이 벨트 위 물체에 속도를 주입할 때 사용

ConveyorBelt

메서드 역할 언제 호출해야 하는가
__init__(gym, sim, env, conveyor_handle, belt_link_name, texture_frame_paths, speed, dt) 텍스처 프레임 로드, 벨트 링크의 로컬 인덱스 조회. texture_frame_paths 중 실제로 존재하지 않는 경로는 경고만 남기고 건너뛰며(예외로 초기화 전체가 죽지 않음), 유효한 경로가 하나도 없거나 belt_link_name을 못 찾으면 텍스처 스크롤을 조용히 비활성화하는 대신 is_texture_enabled 플래그를 False로 노출해 호출부가 직접 확인할 수 있게 함 액터 생성 직후 1회
is_texture_enabled (읽기 전용 속성) belt_link_name을 찾았고 유효한 텍스처 프레임이 1개 이상 로드된 경우에만 True. _scroll_texture()가 매 프레임 이 값을 확인해 스킵 여부를 결정 텍스처 스크롤이 왜 안 되는지 코드에서 직접 확인하고 싶을 때 (if not conveyor.is_texture_enabled: ...)
setup_tensors(belt_length) root/rigid body 상태 텐서 획득, belt_rb_sim_idx 확정, 텍스처 스크롤 속도 계산 gym.prepare_sim(sim) 직후, 다른 텐서 기반 메서드 호출 전 1회
register_item(actor_handle, root_link_index=0) 컨베이어가 관리할 물체를 등록. 등록 순서상 처음 등록된 물체가 기본 거리측정 기준(_distance_ref_item)이 됨. 액터/링크 인덱스가 유효하지 않으면 False를 반환(등록 실패), 성공 시 True 벨트 위에 물체가 올라온 시점(스폰 직후 등)
unregister_item(actor_handle) 물체를 더 이상 관리하지 않도록 제거 벨트 끝에서 다른 공정으로 넘어갈 때
set_item_grabbed(actor_handle, grabbed) 로봇 등이 물체를 붙잡고 있는 동안 물체에 컨베이어 힘이 가해지지 않도록 표시 그리퍼가 물체를 attach/detach하는 매 순간
reset_item_landing(actor_handle) 안착 판정 및 거리측정 기록을 리셋 물체를 재사용(재스폰)해서 다시 벨트 위에 올려놓을 때
move_forward(distance=None) 로컬 +Y 방향으로 이동 시작. distance를 주면 그만큼만 이동 후 자동 정지. 내부적으로 _start_run(direction=+1, distance) 호출 컨베이어를 정방향으로 가동해야 하는 시점
move_backward(distance=None) 로컬 -Y 방향으로 이동 시작. distance를 주면 그만큼만 이동 후 자동 정지. 내부적으로 _start_run(direction=-1, distance) 호출 컨베이어를 역방향으로 가동해야 하는 시점
stop() 즉시 정지. 다음 update()에서 물체 속도도 0으로 리셋됨 가동 중단이 필요한 시점(수동 정지, 비상 정지 등)
set_speed(new_speed) 런타임에 벨트 속도를 변경. 내부적으로 _recompute_texture_scroll_rate()를 호출해 아이템 주입 속도와 텍스처 스크롤 속도가 함께 재계산됨 구간별로 속도를 다르게 가져가야 할 때
update(frame_count=0) 안착 판정, 속도 주입, 거리 갱신/자동 정지, 텍스처 스크롤을 모두 수행(내부적으로 아래 private 헬퍼들을 순서대로 호출) 매 프레임 (ConveyorStepRunner 사용 시에는 runner.update()가 대신 호출해줌)
seconds_to_frames(seconds) self.dt 기준으로 초를 프레임 수(정수, 반올림, 0 이상)로 환산 ConveyorStepRunner가 hold_seconds 대기 프레임 수를 계산할 때 호출. 직접 호출해 프레임 환산에 재사용해도 무방
moved_distance (property) 현재 run에서 기준 아이템이 이동한 거리(m) 반환 거리 기준 이동 진행 상황을 조회하고 싶을 때

ConveyorBelt — 내부(private) 헬퍼 메서드

외부 호출부에서 직접 호출하도록 설계되지 않았으며, 위 표의 초기화/이벤트 메서드 또는 update()가 내부적으로만 사용한다.

메서드 역할 호출하는 곳
_recompute_texture_scroll_rate() belt_length / speed / num_frames를 바탕으로 방향 부호가 빠진(정방향 기준) 프레임당 텍스처 픽셀 이동량(_texture_pixels_per_frame_base)을 재계산. 텍스처가 없거나 belt_length가 없으면 0.0으로 설정 setup_tensors(), set_speed()
_start_run(direction, distance) running=True, direction, target_distance 설정 및 _moved_distance 초기화. 거리측정 기준 아이템(_distance_ref_item)을 현재 등록된 아이템 중 첫 번째로 재설정하고, 모든 아이템의 start_local_y/last_local_y를 None으로 리셋(다음 update()에서 현재 위치로 새로 기록되도록) move_forward(), move_backward()
_get_belt_pose() 벨트 리지드바디의 현재 월드 위치(belt_p)와 회전(belt_r)을 rb_states에서 읽어 반환 update()가 매 프레임 최초 1회 호출
_update_item(st, belt_p, belt_r) -> bool 아이템 하나에 대해: ① z값 변화가 LANDING_Z_STABLE_EPS 이하이고 높이가 LANDING_MIN_HEIGHT 초과이면 안착 판정 ② 가동 중·안착·비-grabbed 상태면 로컬 +Y/-Y 속도를 월드 속도로 변환해 주입하고 _flatten_keep_yaw()로 회전을 수평 보정 ③ 안착 상태에서 정지 중이거나 grabbed면 속도를 0으로 리셋 ④ 거리 추적용으로 _world_to_local()을 이용해 로컬 y 위치를 매 프레임 기록. root_states가 실제로 변경되었으면 True 반환 update()가 등록된 아이템마다 반복 호출
_update_distance_tracking() 거리 기준 이동 중일 때, 기준 아이템(_distance_ref_item)이 제거되었거나 아직 위치 기록이 없으면 start_local_y/last_local_y가 기록된 다른 landed 아이템으로 자동 교체. moved_distance를 갱신하고 target_distance 도달 시 stop() 호출 update()가 매 프레임 호출
_push_root_states(updated_indices) 이번 프레임에 변경된 아이템들의 인덱스만 모아 set_actor_root_state_tensor_indexed로 물리 엔진에 일괄 반영 update()가 변경된 아이템이 하나 이상 있을 때 호출
_scroll_texture() is_texture_enabled이 False면 skip. 그렇지 않으면 direction을 곱해 texture_pixel_pos를 진행시키고, num_frames로 나눈 나머지를 인덱스 삼아 set_rigid_body_texture 호출 update()가 running이고 num_frames > 0일 때 호출

ConveyorMotionStep

컨베이어 한 구간의 이동을 기술하는 데이터 클래스. 실제 동작은 수행하지 않고 ConveyorStepRunner에 의해 소비된다.

생성자 인자 역할
name 스텝 식별용 이름(로그 출력에 사용)
distance 이동 거리(m). None이면 stop() 호출 전까지 무한 이동
direction 'FORWARD' 또는 'BACKWARD'(대소문자 무관). 그 외 값은 ValueError
hold_seconds 이동 완료 후 정지 상태를 유지할 시간(초). 음수는 0으로 clamp
wait_for 스텝을 시작하기 전 만족해야 할 조건 콜백 wait_for(context) -> bool. None이면 조건 없이 즉시 시작
on_enter 이동 시작 직전 실행할 콜백 리스트, 각 콜백은 cb(context) 형태로 호출
on_complete 이동+hold가 모두 끝난 뒤 실행할 콜백 리스트, 각 콜백은 cb(context) 형태로 호출

ConveyorStepRunner

ConveyorMotionStep 리스트를 순차적으로 실행하는 상태 머신. 내부적으로 conveyor.move_forward()/move_backward()를 호출하고 conveyor.running을 폴링해 스텝 전환 시점을 판단한다.

메서드 역할 언제 호출해야 하는가
__init__(conveyor, steps, context=None) 실행할 ConveyorBelt 인스턴스, ConveyorMotionStep 리스트, 콜백에 전달할 임의의 context 객체를 받아 초기 상태(index=0, sub_stage=SUB_MOVING) 설정 컨베이어와 스텝 시퀀스가 모두 준비된 뒤 1회
update(frame_count=0) 매 프레임 호출. 내부적으로 conveyor.update(frame_count)를 먼저 호출한 뒤: 현재 스텝의 wait_for 충족 여부 확인 → (최초 진입 시) on_enter 콜백 실행 후 move_forward/move_backward 호출 → 이동 중(SUB_MOVING)이면 conveyor.running이 False가 될 때까지 대기 → 정지 유지(SUB_HOLD)면 hold_seconds(→conveyor.seconds_to_frames()로 환산)만큼 대기 후 on_complete 콜백 실행 및 다음 스텝으로 진행 매 프레임 (conveyor.update()를 직접 호출하지 말고 이 메서드로 대체할 것)
done (속성) 모든 스텝이 완료되었는지 여부 시퀀스 종료 여부를 확인할 때

ConveyorStepRunner 사용 시 ConveyorBelt.update()를 별도로 호출하면 안 된다(중복 호출 방지)

ConveyorStepRunner — 내부(private) 헬퍼 메서드

외부에서 직접 호출하도록 설계되지 않았으며, 위 update()가 내부적으로만 사용한다.

메서드 역할 호출하는 곳
_current_step() self.steps[self.index] — 현재 실행 중인 스텝 객체 반환 update()가 매 프레임 최초 호출
_advance_to_next_step(step) 현재 스텝의 on_complete 콜백을 전부 실행하고 로그를 남긴 뒤, index를 증가시키고 sub_stage를 SUB_MOVING으로, _entered_current_step/_hold_start_frame을 초기 상태로 리셋. index가 스텝 개수를 넘으면 done=True update()가 SUB_HOLD 상태에서 hold_seconds가 경과했을 때, 또는 hold_seconds=0이라 _enter_hold()가 곧바로 위임할 때
_enter_hold(step, frame_count) step.hold_seconds > 0이면 sub_stage를 SUB_HOLD로 전환하고 _hold_start_frame을 기록, 0이면 바로 _advance_to_next_step() 호출 update()가 SUB_MOVING 상태에서 conveyor.running이 False가 됐을 때

4. 튜닝 파라미터

파라미터 값 용도 / 근거
LANDING_Z_STABLE_EPS 0.0001 dt=1/60 기준, 물체 z가 이 값 이하로 변하면 "더 이상 낙하하지 않는다"(안착)로 판정. dt를 바꾸면(예: 30Hz) 함께 재튜닝 필요
LANDING_MIN_HEIGHT 0.05 m 낙하 초기 오탐(아직 공중인데 안착으로 오판) 방지용 최소 높이. 표준 박스 크기(약 0.1~0.3m급) 전제
speed (기본 0.5) m/s 벨트가 아이템에 주입하는 로컬 +Y/-Y 방향 선속도. set_speed()로 런타임 변경 가능하며, 변경 시 텍스처 스크롤 속도도 함께 재계산됨
dt (기본 1/60) s 물리 스텝 간격 전제값. 텍스처 스크롤 속도(_texture_pixels_per_frame_base) 및 안착 판정 상수와 연동되어 있으므로, 시뮬레이션 스텝 주기를 바꾸면 생성자 인자로 함께 맞춰야 함. seconds_to_frames()의 초→프레임 환산 기준이기도 함
belt_length (생성자 기본값 없음, setup_tensors 인자 기본 3.5) m 텍스처 프레임 전환 속도 계산에 쓰이는 벨트의 실제 길이. 에셋 치수와 일치해야 스크롤 체감 속도가 실제 이동 속도와 맞아떨어짐
num_frames (텍스처 프레임 개수, texture_frame_paths 길이로 결정) 개수 벨트 표면 애니메이션의 프레임 수. 많을수록 부드럽지만 텍스처 전환 호출 빈도가 늘어남
