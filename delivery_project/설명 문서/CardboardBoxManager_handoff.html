CardboardBoxManager 인수인계 문서

1. 목적 / 역할

CardboardBoxManager는 IsaacGym 시뮬레이션 안에서 골판지 상자(cardboard box) 액터 하나를 제어하는 클래스다. 상자의 관절(옆면/윗면 플랩)을 스테이지 단위로 접고, 접힌 상태를 잠그며, 상자 안에 담긴 패키지들과 상자를 올려둔 팔레트(platform)에 대해 매 프레임 강체처럼(텔레포트 방식) 따라붙는 오프셋 고정을 관리한다.

BoxStageRegistry는 "이 스테이지에서는 어떤 관절이 몇 도가 되어야 하고, 어떤 관절을 잠글지"를 이름 기반으로 등록/조회하는 데이터 저장소이며, CardboardBoxManager는 이를 주입받아 사용만 한다(로직과 데이터 분리).

2. 클래스 다이어그램 + 호출 순서 시퀀스

2.1 클래스 관계

classDiagram class BoxStageRegistry { -_stages: dict +__init__() +register(name, joint_targets_deg, lock_joints, base) +get(name) dict +names() list } class CardboardBoxManager { 주요 멤버 변수 -gym, sim, env, handle -stage_registry: BoxStageRegistry -dof_dict, dof_names, num_dofs -targets, current_targets -children: dict -joint_speed: float -root_states: Tensor %% 초기화 메서드 +__init__(gym, sim, env, handle, stage_registry, ...) +setup_tensors() +set_initial_spawn_stage(name) %% 내부(private) 헬퍼 메서드 -_setup_dof_properties() -_set_joint_target(joint_name, target_angle) -_force_spawn_stage_by_name(stage_name) %% 매 프레임 호출 메서드 +update_joints(dt) +update_children() +update_platform_lock() +draw_debug_visuals(viewer) %% 이벤트/조건부 호출 메서드 +apply_stage(name) +set_joint_speed(new_speed) / get_joint_speed() +lock_joint(name) / unlock_joint(name) +register_child(handle) / unregister_child(handle) +lock_children_offsets() / unlock_children() / +scan_and_capture(candidates, getter) +attach_to_platform(handle) / detach_from_platform() / } CardboardBoxManager --> BoxStageRegistry : stage_registry로 주입받아 조회 및 적용

2.2 초기화 순서

sequenceDiagram participant Caller as 호출부(env 생성 코드) participant Mgr as CardboardBoxManager Caller->>Caller: gym.create_actor(...) → handle Caller->>Mgr: CardboardBoxManager(gym, sim, env, handle, stage_registry, ...) Caller->>Caller: (모든 env의 액터 생성이 끝난 뒤) gym.prepare_sim(sim) Caller->>Mgr: setup_tensors() Caller->>Mgr: set_initial_spawn_stage("stage_name") (박스가 초기에 접혀있어야 하는 경우)

setup_tensors()를 호출하기 전에 lock_children_offsets, update_children, attach_to_platform, update_platform_lock, scan_and_capture 등을 호출하면 self.root_states가 None이라 에러가 난다.

생성자 호출 → prepare_sim → setup_tensors → set_initial_spawn_stage 순서를 지켜야 한다.

2.3 사용법 예시 (~/isaacgym/python/delivery_project/tests/test_cardboardbox.py 기준) 

registry = BoxStageRegistry()
registry.register("unfolded_flat", {
    "joint_right_to_front": 0.0, "joint_right_to_back": 0.0, "joint_front_to_left": 0.0,
    "joint_right_to_down": 0.0, "joint_left_to_down": 0.0, "joint_front_to_down": 0.0, "joint_back_to_down": 0.0,
    "joint_right_to_up": 0.0, "joint_left_to_up": 0.0, "joint_front_to_up": 0.0, "joint_back_to_up": 0.0,
})
registry.register("fold_sides", {
    "joint_right_to_front": 90.0, "joint_right_to_back": 90.0, "joint_front_to_left": -90.0,
})
registry.register(
    "close_fb_bottom",
    joint_targets_deg={"joint_front_to_down": -90.0, "joint_back_to_down": 90.0},
    base="fold_sides",
)
registry.register(
    "close_rl_bottom",
    joint_targets_deg={"joint_right_to_down": -90.0, "joint_left_to_down": 90.0},
    base="close_fb_bottom",
    lock_joints=["joint_right_to_down", "joint_left_to_down",
                    "joint_front_to_down", "joint_back_to_down"],
)
registry.register(
    "close_top",
    joint_targets_deg={
        "joint_right_to_up": 90.0, "joint_left_to_up": -90.0,
        "joint_front_to_up": 90.0, "joint_back_to_up": -90.0,
    },
    base="close_rl_bottom",
    lock_joints=["joint_right_to_up", "joint_left_to_up",
                    "joint_front_to_up", "joint_back_to_up"],
)

# fix_base_link=True로 스폰하면 중력을 무시하고 그 자리에 고정
box_asset = load_asset(gym, sim, "urdf/cardboard_box/v2/box_v2.urdf", fix_base_link=True, density=100.0)
box_handle = gym.create_actor(env, box_asset, gymapi.Transform(p=gymapi.Vec3(0.0, 0.0, 1.0)), "box_test", -1, 0)
box_manager = CardboardBoxManager(gym, sim, env, box_handle, stage_registry=registry, joint_speed=1.2)

gym.prepare_sim(sim)

box_manager.setup_tensors()

# 루프에서 조건적으로 메서드 호출
box_manager.apply_stage("fold_sides")
box_manager.lock_joint("joint_right_to_front")
box_manager.unlock_joint("joint_right_to_front")

# 루프에서 매 프레임 필수 호출:
box_manager.update_joints()
box_manager.update_platform_lock()
box_manager.update_children()

CardboardBoxManager는 MotionStep/StepRunner가 없고, 다른 컨트롤러(ArmMotionStep 등)의 on_start/on_complete 콜백에서 호출당하는 존재다.
단독 테스트 test_cardboardbox.py에서는 그 역할을 흉내 낸 소형 시퀀서로 대체한다:

class BoxTestSequencer:
    """(name, action_fn, hold_frames) 리스트를 순서대로 실행."""
    def update(self, frame_count):
        name, action_fn, hold_frames = self.steps[self.index]
        if not self._entered:
            action_fn(self.box_manager)   # 예: lambda bm: bm.apply_stage("fold_sides")
            self._entered = True
            self._hold_start_frame = frame_count
        if frame_count - self._hold_start_frame >= hold_frames:
            self.index += 1
            self._entered = False

steps = [
    ("FOLD_SIDES", lambda bm: bm.apply_stage("fold_sides"), 90),
    ("CLOSE_FB_BOTTOM", lambda bm: bm.apply_stage("close_fb_bottom"), 90),
    ("CLOSE_RL_BOTTOM", lambda bm: (bm.apply_stage("close_rl_bottom"),
                                     bm.lock_joint("joint_right_to_down"),
                                     bm.lock_joint("joint_left_to_down")), 90),
    ("CLOSE_TOP", lambda bm: bm.apply_stage("close_top"), 90),
]

seq = BoxTestSequencer(box_manager, steps)

# 루프에서 시퀀서 호출
if not seq.done:
    seq.update(frame_count)

hold_frames(예: 90)는 다음 스텝으로 넘어가기 전 몇 프레임을 기다릴지다. apply_stage()는 목표각을 즉시 설정만 할 뿐, 실제로 그 각도까지 도달하는 건 update_joints()가 매 프레임 joint_speed(기본 1.2 rad/s) 속도로 서서히 보간하기 때문에, 목표각(예: 90°≈1.57rad)까지 걸리는 시간(1.57/1.2 ≈ 1.3초)보다 여유 있게 잡아야 다음 콜백이 이전 접기가 끝나기 전에 발동하지 않는다.

3. Public API 레퍼런스

BoxStageRegistry

메서드 역할 호출 시점
__init__() 스테이지 저장소(self._stages = {})를 빈 딕셔너리로 초기화 레지스트리 인스턴스 생성 시 1회
register(name, joint_targets_deg, lock_joints=None, base=None) 스테이지 이름에 관절 목표각(도)과 잠글 관절 목록을 등록. base를 주면 기존 스테이지 값을 먼저 복사한 뒤 덮어써서 "이전 스테이지를 포함하는" 누적 스테이지를 만들 수 있음 시뮬레이션 시작 전, 초기 설정 단계에서 한 번씩
get(name) 등록된 스테이지 딕셔너리(joint_targets, lock_joints) 반환 CardboardBoxManager.apply_stage 내부에서 사용
names() 등록된 스테이지 이름 목록 디버깅/검증용

CardboardBoxManager

메서드 역할 언제 호출해야 하는가
__init__(...) DOF 속성 초기화(_setup_dof_properties 호출), dof_dict/link_dict 구성, 상자 자신의 콜리전 필터를 공유 비트로 설정 액터 생성 직후 1회
apply_stage(stage_name) 레지스트리에서 스테이지를 조회해 관절마다 _set_joint_target을 호출하여 self.targets에 반영 스테이지 전환이 필요한 시점
set_initial_spawn_stage(stage_name) 내부적으로 _force_spawn_stage_by_name을 호출: apply_stage + 관절 각도를 강제로 그 값에 동기화(속도 보간 없이 즉시) + lock_joints 잠금 스폰 직후, 1회 (setup_tensors() 이후)
update_joints(dt=1/30) self.targets를 향해 joint_speed 제한 속도로 current_targets를 보간하고 물리 엔진에 위치 목표로 주입 매 프레임
set_joint_speed(new_speed) 관절 접기/펴기 속도(rad/s, joint_speed)를 실행 중에 변경. update_joints가 매 프레임 self.joint_speed를 참조하므로 재시작 없이 다음 프레임부터 반영됨. 진행 중인 보간의 남은 거리는 유지되고 스텝 폭만 바뀜. 0 이하 값은 ValueError 런타임에 접기/펴기 속도를 동적으로 바꾸고 싶을 때(예: 특정 구간만 느리게/빠르게)
get_joint_speed() 현재 설정된 joint_speed를 반환 현재 속도 값을 조회하고 싶을 때
lock_joint(joint_name) 해당 관절의 상/하한을 현재 목표각으로 고정하고 게인을 크게 올려 외력에 안 밀리게 함 스테이지 전환 후 해당 관절을 완전히 고정하고 싶을 때
unlock_joint(joint_name) 관절 한계/게인을 기본값으로 되돌림 다시 움직여야 하는 관절에 대해 잠금 해제할 때
draw_debug_visuals(viewer, ...) 각 링크 원점 및 두 접합부(left/back) 기준점에 디버그 구체 표시 뷰어가 있는 디버그 세션에서 매 프레임(선택)
setup_tensors() 루트 상태 텐서 획득, box_actor_idx 확정 gym.prepare_sim(sim) 직후, 다른 텐서 기반 메서드 호출 전에 반드시 1회
register_child(actor_handle) 패키지를 상자 소속으로 편입, 콜리전 필터를 공유 비트로 변경 (서로 충돌 무시) 패키지가 상자 안에 들어왔다고 판단될 때 (수동 또는 scan_and_capture 내부에서)
unregister_child(actor_handle) 패키지를 상자 소속에서 제외, 콜리전 필터를 원래 값으로 복원 개별 패키지를 상자에서 뺄 때
lock_children_offsets() 현재 시점 기준으로 각 자식의 상자 대비 상대 위치/회전을 고정 패키지 적재가 끝나고, 상자를 이동시키기 전에
unlock_children() 등록된 모든 자식을 일괄 unregister_child 처리, children_locked=False 하역(상자를 열어 내용물을 자유 물리로 되돌릴 때) 할 때
update_children() children_locked일 때 매 프레임 자식들을 상자 기준 고정 오프셋 위치로 텔레포트 매 프레임
scan_and_capture(candidate_handles, root_states_getter) 후보 패키지 중 상자 중심 기준 반경/높이 안에 있는 것들을 새로 편입 패키지 적재 구간(컨베이어→상자 투입 등)에서
attach_to_platform(platform_actor_handle) 상자 자신을 팔레트 기준 상대 오프셋으로 고정 상자를 팔레트에 얹는 시점 1회
detach_from_platform() 팔레트 추종 해제 상자를 팔레트에서 내릴 때
update_platform_lock() platform_locked일 때 매 프레임 상자를 팔레트 기준 오프셋 위치로 텔레포트 매 프레임

CardboardBoxManager — 내부(private) 헬퍼 메서드

외부 호출부에서 직접 호출하도록 설계되지 않았으며, 위 표의 초기화/이벤트 메서드가 내부적으로만 사용한다.

메서드 역할 호출하는 곳
_setup_dof_properties() 모든 DOF를 DOF_MODE_POS(위치 제어)로 설정하고, 기본 강성/감쇠/토크(_DEFAULT_STIFFNESS/_DEFAULT_DAMPING/_DEFAULT_EFFORT)를 일괄 적용 __init__ 내부에서 1회
_set_joint_target(joint_name, target_angle) 이름으로 찾은 관절 하나의 목표각(라디안)을 self.targets[idx]에 설정 apply_stage가 스테이지의 joint_targets 항목마다 반복 호출
_force_spawn_stage_by_name(stage_name) apply_stage 호출 → current_targets를 targets로 즉시 동기화 → set_actor_dof_states/set_actor_dof_position_targets로 물리 엔진 상태 강제 동기화 → 스테이지의 lock_joints마다 lock_joint 호출 set_initial_spawn_stage가 그대로 위임

4. 튜닝 파라미터

파라미터 값 용도 / 근거
_DEFAULT_STIFFNESS 400.0 일반 접기 동작 시 PD 위치 제어 강성. 관절이 목표각을 따라가되 약간의 유연성(충돌 시 밀림 여지)을 허용하는 수준
_DEFAULT_DAMPING 40.0 기본 감쇠. stiffness 400과 짝을 이뤄 과도한 진동 없이 부드럽게 수렴하도록 설정된 값(대략적인 임계 감쇠 근방 비율)
_DEFAULT_EFFORT 100.0 기본 최대 토크 한도. 접히는 과정에서 장애물(패키지 등)과 부딪혀도 무리하게 뚫고 지나가지 않도록 제한
_LOCKED_STIFFNESS 15000.0 잠금 시 강성. 외력에 잘 밀리지 않는 강체에 가깝게 만듦
_LOCKED_DAMPING 800.0 잠금 시 감쇠. 강성 상승에 비례해 함께 올려 진동을 억제
_LOCKED_EFFORT 100000.0 잠금 시 최대 토크. 충돌/외력에도 각도가 흔들리지 않게 함
joint_speed (기본 1.2) rad/s update_joints에서 current_targets가 targets를 따라갈 수 있는 최대 각속도. 값이 클수록 스테이지 전환 애니메이션이 빨라짐. 인스턴스별 생성자 인자로 조정 가능
capture_radius_xy (기본 0.5) m scan_and_capture에서 패키지를 자동 편입할 xy 평면상 반경, 상자 크기 변경시 변경 필요
capture_height (기본 0.6) m 편입 판정용 z축(높이) 허용 범위, 상자 크기 변경시 변경 필요
debug_left_tip_offset / debug_back_tip_offset Vec3(-0.505,0,0) / Vec3(0,0.3,0) link_left/link_back 기준 로컬 오프셋. 디버그 시각화 전용이며 URDF 치수에 종속

5. 참고사항

  • set_initial_spawn_stage 사용시 박스 주변에 충돌할 물체가 있는 경우 끼임 발생 가능
  • 박스가 완전히 연결된 구조가 아니어서 link_left과 link_back사이에 분리 발생 가능. draw_debug_visuals로 해당 위치 확인
